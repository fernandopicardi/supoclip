# Caption customization

Settings → Caption defaults now includes top/center/bottom presets, a vertical
position slider, keyboard/drag adjustment in the static preview, 1–8 words per
caption, contrast background, uppercase and spoken-word highlighting with an
accent color. Font, size and color remain separate preferences. Save preferences
to persist the defaults in the account. No video is generated by these controls.

The creation form starts with the account defaults and allows per-video changes.
The backend snapshots the layout in task source metadata before queueing it.
New directed edits copy the account defaults. Existing directed edits and clip
drafts retain their saved styles. The clip editor lists system and account fonts.
Font ownership is checked before saving a draft or starting an export.

## Database

The additive migration is
`frontend/prisma/migrations/20261028140000_caption_style_preferences/migration.sql`.
It adds only `users.default_caption_style JSONB NOT NULL DEFAULT '{}'`.
Apply it before starting the new frontend/backend. Fresh installs include the
column in `init.sql`. An older local installation without Prisma migration
history must apply this SQL alone; do not replay its initialization or unrelated
migrations. It does not modify font choices, recordings, sessions or drafts.

## Validation without video rendering

Frontend: caption-layout unit tests, preferences route tests, typecheck, lint,
and `pnpm exec playwright test --config playwright.captions.config.ts`.
The browser test stubs APIs and exercises preview, saving, reload and mobile.
Backend: caption preferences, editor documents/routes, font registry and mocked
task propagation tests. ASS text generation is checked without media encoding.
Final video appearance and karaoke timing require a separately approved export.

### Preview / export typography

Settings sizes are CSS pixels in a 300px reference frame (24 means 12 CSS px
in the 150px settings preview). The preview scales with its actual container.
Before creating a new edit or rendering an advanced generation, the backend
converts CSS em pixels to libass font-height units using the selected font's
ascent, descent and units-per-em. For Nunito Sans, 24 becomes 118 in a
1080-wide editor document and 79 at width 720. The editor's range now allows
these larger font-height values. Existing documents retain their saved sizes;
reapply account defaults explicitly when upgrading an existing edit.

The `NunitoSans` API name points to its static Bold/700 face because libass
selected the variable file's default ExtraLight face. Browser font loaders
request fresh font assets and specify the same bold weight. This change does
not rewrite account preferences, existing timelines, recordings or exports.

The reused backend runtime is patched to the Authlib wheel and hash in `uv.lock`
(1.9.1). This resolves the critical finding reported by the image gate during
this release without replacing unrelated installed dependencies. Run the image
security check on both final images before activation.
